## 概要

タスク管理の基盤となる機能で、他のタスク機能はこのページのテーブルと API の上に作る。タスク CRUD とプロジェクト内連番 ID（`KEY-N` 形式。例は `ENG-42`）、プロジェクト単位のカスタムステータス、担当者を扱う。優先順位・締切（Soft / Hard）・開始予定日・進捗率、親子タスクとブロッキング依存関係、プロジェクト単位のラベル（export / import を含む）、マイルストーンも含む。他の機能への依存は無い。

## 振る舞い

### プロジェクトキー

プロジェクトの `key` はテナント内で一意の英大文字識別子（例は `ENG`、`BACK`、`WEB`）で、`KEY-N` 形式に使う。形式は `^[A-Z][A-Z0-9]{1,9}$`（制約 `projects_key_format`）、一意性は `projects_key_tenant_unique`（`tenant_id`, `key`）で保つ。

- プロジェクト作成 API で指定すれば、その値を検証して使う。重複はエラーになる
- 省略するとプロジェクト名の英数字を大文字にして先頭 10 文字を取る。例は "Backend API" から `BACKENDAPI`
- 英数字が足りないか形式に合わなければ `PROJ` にする
- 自動生成のキーが重複したら、先頭 6 文字とランダムな 4 文字に作り直す

### 連番 ID

`project_task_counters.last_seq` を `SELECT ... FOR UPDATE` でロックしてインクリメントする。行が無ければ `1` で作る。

### カスタムステータス

通常のプロジェクトを作ると `Backlog` / `Todo`（`is_default`）/ `In Progress` / `Done`（`is_done_state` と `is_default_done`）の 4 つを自動で挿入する。個人プロジェクトは `Todo`（`is_default`）と `Done` の 2 つである。タスク作成 API は `status_id` を必須としており、`is_default` を自動では補わない。既定値を使うのはクライアント側である。

完了ステータスは複数持てる（`Done` と `No Planning` のように）。そのうち 1 つに `is_default_done` を付け、CLI の `tasks complete`・タスク詳細の完了ボタン・GitHub Issue の close 同期はここへ移す。`is_default_done` の付いたステータスが無いプロジェクトでは並び順で最初の完了ステータスを使う。

- `is_default_done` は完了ステータスにしか付けられず、付け替えると他からは自動で外れる。付いているものを直接 `false` にする更新は 400 になる
- 完了ステータスが 1 つも無い状態にはできない。最後の 1 つは `is_done_state` を外せず、削除もできない
- 完了ステータスを外したり削除したりして `is_default_done` の持ち主が消えると、並び順で最初の完了ステータスへ付け直す
- 完了を外したステータスにあるタスクは `completed_at` が消える
- 完了にしたステータスにあるタスクと、完了へ移したタスクには `completed_at` が入る。既に値があれば保つ
- `is_default` のステータスは削除できない（400）

### 締切と開始予定日

API は Soft 締切 < Hard 締切を要求し、同時刻も 400 にする。DB の CHECK（`soft_before_hard`）は soft ≤ hard である。

開始予定日 `planned_start_on` は DATE で NULL にできる。更新は `planned_start_on` と `clear_planned_start_on` で行い、同時に指定すると解除が優先する（`clear_soft_deadline` と同じ）。Soft 締切との前後関係は DB の CHECK でもサーバーの検証でも見ない。変更は `planned_start_changed` の履歴に記録する。

### 説明文

`description` は Markdown で、上限は 100,000 文字である。バイトではなく文字で数える（`payload::tasks::MAX_DESCRIPTION_LEN`）。作成・更新で超過すると 400 になる。上限の導入前に保存された超過行は移行せず、本文を送らない更新はそのまま通る。タスク詳細の SSR は同じ値を超える本文を描画せずプレーン表示にする。

本文中の http / https の絶対 URL のリンクの先頭には、リンク先サイトの favicon を出す。画像は `GET /v1/favicons/{host}` が取得して配信し、取れないときは汎用アイコンになる。コメント、ドキュメント、レビュー指摘の本文も同じ描画である。規則は [KFM の描画](/dev/frontend/kfm-phase1-implementation) に書く。

### 担当者

`role` は自由な文字列で、サーバーは値の種類を検証しない。画面は `primary` を、一括更新（[タスク拡張](/dev/features/tasks/extensions)のバルク操作）は `assignee` を入れるので、両方が混在する。

担当者欄（タスク作成ダイアログ・タスク詳細・一覧の行）は、候補の後ろに部署・チームの行を出す。選ぶとその部署・チームの候補全員を担当者に加える。API は利用者ごとに送り、作成は `assignees` に全員を載せ、作成後は 1 人ずつ `POST` する。部署・チームは `tenant_members` の自由記述をそのまま使うので、表記が違えば別の行になる。

### 依存関係と親子

循環依存はリレーション追加時にサーバー側で BFS を行って検出し、`409 Conflict` を返す。トランザクションを SERIALIZABLE にして、逆向きの追加が同時に走って検出をすり抜けることを防ぐ。親子関係（`parent_task_id`）の循環も更新時に検出する。

親タスクは `PUT /tasks/{id}` の `parent_task_id`（設定・変更）と `clear_parent_task_id`（解除）で変える。

### 削除

タスクの削除は `deleted_at` によるソフトデリートである。物理削除の API は無い。

## API

URL 基底パスは `/v1/tenants/{tenant_id}/projects/{project_id}` である。

### タスク

| メソッド | パス | 説明 |
|---|---|---|
| `GET` | `/tasks` | 一覧（フィルター・ソート・ページング） |
| `POST` | `/tasks` | 作成 |
| `GET` | `/tasks/{id}` | 取得（UUID または `KEY-N`、例は `ENG-42`） |
| `PUT` | `/tasks/{id}` | 更新（全フィールド optional） |
| `DELETE` | `/tasks/{id}` | ソフトデリート |
| `POST` | `/tasks/{id}/archive` | アーカイブ |
| `POST` | `/tasks/{id}/unarchive` | アーカイブ解除 |

`GET /tasks` のクエリは次のとおりである。

| パラメータ | 型 | 説明 |
|---|---|---|
| `status_id` | UUID? | |
| `priority` | string? | DB 値（`high` など）。不明な値は 400 |
| `assignee_id` | UUID? | |
| `created_by` | UUID? | 指定した利用者が作成したタスクのみ |
| `label_id` | UUID? | 指定ラベルが付与されたタスクのみ |
| `milestone_id` | UUID? | |
| `sprint_id` | UUID? | |
| `parent_task_id` | UUID? | サブタスク一覧 |
| `planned_start_from` | date? | 開始予定日がこの日以降（`YYYY-MM-DD`、両端含む） |
| `planned_start_to` | date? | 開始予定日がこの日以前（両端含む）。`from > to` は 400。どちらかを指定すると開始予定日が未設定のタスクは除外する |
| `root_only` | bool | 既定 false。親が同じ絞り込みの結果に含まれないタスクだけを返す（List 表示が使う） |
| `is_archived` | bool | 既定 false |
| `sort` | string | `created_at_desc`（既定）、または `title` / `assignee` / `priority` / `deadline` に `_asc` / `_desc` を付けた値 |
| `limit` | u32 | 既定 50、1〜200 に丸める |
| `offset` | u32 | ページ番号で飛ぶ一覧（表形式）が使う |
| `cursor` | string? | 前のページの `next_cursor`。`offset` と同時指定は 400。カーソルは `sort` ごとに別物である |

続きを読み足す一覧は `offset` ではなくカーソルを使う。応答の `total` は絞り込み後の総数で、件数の表示とページ番号の算出に使う。「まだ残っているか」の判断には `next_cursor` を使う。応答はステータスと利用者を ID または要約で返し、`subtask_count` は持たない。

`POST /tasks` は `title` と `status_id` が必須である。`priority` は JSON の値（`High` など。[優先順位 enum](/dev/features/tasks)）で送る。`custom_field_values` は[カスタムフィールド](/dev/features/tasks/custom-fields)の値である。作成と更新の応答は `GET /tasks/{id}` と同じ形（`TaskDetailResponse`）で、`TaskResponse` のフィールドに `custom_field_values`・`mentions`・`reactions`・`attachments`（[拡張](/dev/features/tasks/extensions)の添付の一覧と同じ要素）を足している。

`PUT /tasks/{id}` の規則は次のとおりである。

- 値をクリアするために `clear_description` / `clear_parent_task_id` / `clear_milestone_id` / `clear_sprint_id` / `clear_soft_deadline` / `clear_hard_deadline` / `clear_planned_start_on` / `clear_estimated_minutes` を持つ
- `label_ids` は集合の置き換え、`add_label_ids` / `remove_label_ids` は差分である
- `assignees` は担当者集合の置き換えで、既存の担当者の役割は保つ
- 完了済みのスプリントへの割り当ては 409 になる

| `GET` | `/tasks/{id}/assignees` | 一覧 |

### 依存関係

| メソッド | パス | 説明 |
|---|---|---|
| `GET` | `/tasks/{id}/relations` | 一覧（`parent` / `subtasks` / `blocks` / `blocked_by`） |
| `POST` | `/tasks/{id}/relations` | 追加（`type` と `target_task_id`） |
| `DELETE` | `/tasks/{id}/relations/{relation_id}` | 削除 |

`POST` はどちらのタスクからでも設定できる。`blocks` と `blocked_by` で反対側から設定しても、結果は同一レコードである。

| `type` | 意味 |
|---|---|
| `"blocks"` | 現タスクが `target` をブロックする |
| `"blocked_by"` | 現タスクは `target` にブロックされている |

`target_task_id` は同じプロジェクトのタスクの UUID に限る。同じ関係の重複と循環は 409 になる。`GET` の応答の各要素は `TaskResponse` の全フィールドで、`blocks` と `blocked_by` にはさらに `relation_id` が付く。

### リンクの favicon

説明文などの外部リンクに出す favicon の配信である。基底パスは上のプロジェクト配下ではなく `/v1` である。

| メソッド | パス | 説明 |
|---|---|---|
| `GET` | `/v1/favicons/{host}` | `https://{host}/favicon.ico` を取得して返す。要認証（セッション、PAT、Device Token） |

- `host` は小文字、ドット必須、ラベル 63 文字以下、全長 253 文字以下。合わなければ 404 になる
- 取れた画像（ICO / PNG / JPEG / GIF / WebP）は `Cache-Control: private, max-age=86400` で返す。サーバー側は Redis に 7 日保存する
- 取れない時（画像でない、private 宛て、タイムアウト、64 KiB 超）は 200 で汎用アイコン（`image/svg+xml`、`private, max-age=3600`）を返し、サーバー側は 1 時間保存する。サーバーに残す画像は 64 KiB までで、超える応答は取れなかった扱いにする
- 取得は全ホップ合わせて 8 秒（1 ホップは 5 秒）で打ち切り、取れなかった扱いにする。同時取得が 16 件を超えた分は保存せず `no-store` で汎用アイコンを返す
- キャッシュに無い host を外へ取りに行く回数は、利用者ごとに 10 分で 30 回までである。超えた分は取りに行かず、保存せずに `no-store` で汎用アイコンを返す。キャッシュ済みの host は数えない
- 接続先は Webhook と同じ規則で検査する（private、link-local、メタデータ、loopback は拒否）。リダイレクトは 3 回まで追い、各ホップで検査する。接続先のポートは常に 443 で、リダイレクト先も 443 以外のポートは拒否する
- 認証を要するのは、無認証だと誰でもこのサーバーを任意ホストへの GET の踏み台にできるためである。認証済みの利用者による Redis の使い切りは、画像の上限と取得回数の上限で抑える

## 認可

| 操作 | 誰が | スコープ |
|---|---|---|
| タスク閲覧 / 作成 / 更新 / アーカイブ | プロジェクトに入れる人、またはテナントオーナー | `read:task` / `write:task` |
| タスク削除（ソフト） | 作成者、またはテナントオーナー | `write:task` |
| ステータス / ラベル管理 | プロジェクトに入れる人、またはテナントオーナー | `write:task` |
| マイルストーン管理 | プロジェクトに入れる人、またはテナントオーナー | `read:milestone` / `write:milestone` |

「プロジェクトに入れる人」は、テナントの所属を継承した人と、そのプロジェクトに明示 ACE（`project_members` の行）を持つ人である。

- プロジェクトにメンバーを 1 人も指定していなければテナントメンバー全員が入れる
- 指定があれば明示 ACE を持つ人だけが入れる
- 明示 ACE はテナント所属と独立に残るので、テナントに行が無い人でも明示 ACE のあるプロジェクトにはゲストとして入れる。テナント全体には入れない

判定の詳細は[テナント / プロジェクト認可](/dev/design/tenant-project-authz)に書く。

## 画面

ページの URL は次のとおりである。

| URL | 内容 |
|---|---|
| `/{tenant}` | ホーム（ダッシュボード） |
| `/{tenant}/my-tasks` | My Tasks |
| `/{tenant}/projects/{KEY}/tasks` | 一覧（List / Table 切替。`?view=table`） |
| `/{tenant}/projects/{KEY}/tasks/{KEY}-{N}` | 詳細 |
| `/{tenant}/projects/{KEY}/settings` | ワークフロー・ラベル・カスタムフィールドの管理 |

一覧の List 表示はステータスごとにタスクをグループにして並べ、行をドラッグして別のグループへ落とすとステータスが変わる。落とし先はグループの全域（見出し・行の隙間・末尾の余白・空のグループ・折りたたんだグループの見出し）で、保存は落としたときに 1 回だけ行う。通過しただけのグループには保存しない。入力欄と行の中に開いた一覧からは掴まず、タッチでは長押しのあとに動かすと掴む。広い画面では一覧の右に詳細を開く。サブタスクは親の行の配下に描く。親行は既定では閉じていて、行の矢印で開く。環境設定「タスク一覧でサブタスクを最初から展開する」を有効にすると親行を開いた状態で描き、サブタスクが無い親行は閉じた見た目のままにする。矢印で個別に閉じた行はその画面を開いている間だけ閉じたままで、設定を切り替えると全行が設定に従う。

List 表示の行は、一覧の幅が 48rem 以上なら担当・期限・優先度を列で並べてその場で変更でき、タイトルの下の ID を押すとコピーできる。それより狭いときは 2 段に積み、担当・期限・優先度は表示だけにして詳細で変更する。ID のコピーは画面幅が 768px 以下では出さない。

親タスクの変更はタスク詳細のサブタスク欄（ページ・オーバーレイ・右ペイン共通）で行う。同じプロジェクトのタスクをキーまたはタイトルで検索して選ぶ。自分自身・現在の親・直下の子は候補から除き、深い子孫を選ぶと backend の 409 を理由つきで表示する。

ブロック関係の設定と表示もタスク詳細のブロック関係の欄（ページ・オーバーレイ・右ペイン共通）で行う。`blocked_by` を先に、`blocks` を次に並べ、相手をキーまたはタイトルで検索して追加する。自分自身と既に関係のあるタスクは候補から除き、循環や重複は backend の 409 を理由つきで表示する。未完了のブロッカーが残っているときは欄の見出しに件数を出す。

マイルストーンは、カレンダーの最上段に期日のフラグとして出す。

### キーボードショートカット

修飾キー無しの単打キーで操作する（`composables/useKeyboardShortcuts.ts`）。Shift の有無は区別しない。

| キー | 画面 | 動作 |
|---|---|---|
| `T` | タスク一覧（`tasks/+Page.vue`） | タスク作成モーダルを開く。一覧本体が表示されていないとき（読み込み中・エラー・テナント／プロジェクト未解決）は何もしない |
| `T` | ホーム（`HomeDashboard.vue`） | タスク作成モーダルを開く。作成ボタンが押せないとき（プロジェクト 0 件・取得失敗）は何もしない |
| `T` | ドキュメント詳細（`DocumentDetail.vue`） | 選択範囲をタイトルにしてタスク作成ダイアログを開く。「タスクを作成」ボタンが出ていないとき（読み込み中・エラー・対象外・編集中）は何もしない |

次のときは発火しない。

- 入力中（`input` / `textarea` / `select` / `contenteditable` の中）
- IME 変換中（`isComposing` または `keyCode` 229）
- ダイアログが開いている（`[role="dialog"]` / `dialog[open]` がある）。タスク詳細オーバーレイや確認ダイアログの上に重ねない
- 修飾キー付き（Ctrl / ⌘ / Alt）。ブラウザ・OS・既存の ⌘B / ⌘S と衝突させない
- キーの押しっぱなし（`repeat`）・他の処理が既に `preventDefault` したもの

## 未実装と既知の制限

- カンバンボードの画面が無い。カスタムステータスを列にして、ドラッグでステータス変更と列の並び替えを行う案がある。保存済みビューの `view_type` には `board` があるが、それを描く画面は無い
- マイルストーンの管理画面が無い。マイルストーンは API で作成する
- 依存関係のグラフ表示が無い。タスク詳細の欄で一覧できるだけで、図にして見せる画面は無い

| 2026-05-29 | ステータスはプロジェクト単位のカスタムステータスとし、ハードコードしない | 記録なし |
| 2026-05-29 | 連番 ID は `SELECT FOR UPDATE` でアトミックに採番し、`KEY-N` 形式で表示する | 記録なし |
| 2026-05-29 | ラベルは `project_id` でプロジェクト単位にする | 記録なし |
| 2026-10-16 | `planned_start_on` と Soft 締切の前後関係を DB の CHECK でもサーバーの検証でも見ない | 計画用の値で前後が逆でも壊れるものがない。締切は TIMESTAMPTZ のため、日付との比較がタイムゾーン次第で正しい組を弾いてしまう |
| 2026-11-01 | 説明文の上限を 100,000 文字にする | タスク詳細の SSR は Markdown を同期で描画するため、長大な本文で server プロセスを塞がないようにする |
| 2026-11-03 | 親タスクの変更は `PUT /tasks/{id}` の `parent_task_id` / `clear_parent_task_id` で行い、UI はタスク詳細のサブタスク欄に置く | 記録なし |
| 2026-11-04 | 続きを読み足す一覧は `offset` ではなくカーソルを使う | 取得の間にタスクが増減すると `offset` の境界がずれ、境界の行がどちらのページにも出なくなる |
| 2026-11-04 | 「まだ残っているか」の判断に `total` を使わず `next_cursor` を使う | 総数は取得中に動くので、比較では終わらないことがある |
| 2026-11-09 | ブロック関係の UI は既存の GET/POST/DELETE `/relations` をそのまま使い、タスク詳細のサブタスク欄の下に置く | API と仕様書は揃っていて、無かったのは画面だけ |
| 2026-11-09 | 設定で開いた親行は、サブタスクが 0 件なら作成欄を出さず描かない | 親行だけではサブタスクの有無が分からないので全行で取りに行く。0 件の行ごとに作成欄や読み込み中が並ぶと一覧が読めなくなる |
| 2026-11-09 | 設定で開いた親行のサブタスク取得は、フォーカス復帰では取り直さず 30 秒は新鮮として扱う。行の変更による取り直しは残す | 表示中の親行の数だけ取得が立つので、フォーカスのたびに全行を取ると多すぎる。子のステータスなどの反映は行の変更後の取り直しで足りる。ただし行の変更ごとに表示中の親行の数だけ再取得される。`has_subtasks` を API に足せば減らせる |
| 2026-11-09 | リンクの favicon の取得は `/favicon.ico` 固定にし、HTML の `<link rel="icon">` は解析しない | HTML の取得と解析にはサイズと時間の上限が別に要り、相対 URL の解決や候補の選別で実装が膨らむ。無いサイトは汎用アイコンで外部リンクだと分かる |
| 2026-11-09 | favicon の取得に全ホップ合わせた 8 秒の上限と、利用者ごとの取得回数の上限（10 分で 30 回）を置き、サーバーに残す画像を 64 KiB までにする | 認証済みの利用者なら誰でも任意の host を要求できる。1 ホップごとの上限だけではリダイレクトのたびに掛け直されて同時取得の枠を長く占有でき、ワイルドカード DNS の host を連番で叩けば Redis（セッションも載る）を埋められる。回数の上限は、初めて開いた長い文書の外部リンクが通り、連番の取得は 1 時間に 180 件ほどで止まる値にした。キャッシュ済みの host は数えない |
| 2026-11-09 | favicon のリダイレクト先は 443 だけを許す | 任意のポートを指せると、公開 IP のポートの開閉を応答時間から探れる |
