## 概要

テナント Admin は、設定のメンバー画面から自動化用の BOT を作成できる。
BOT は作成元の一つのテナントだけに属し、PAT で API と既存 CLI を利用する。
管理者は BOT の作成、停止、再開、PAT の発行と取り消しを行える。
BOT は画面と対話用のセッションには入れない。
CLI の改修は範囲外で、既存の CLI に BOT の PAT を渡して使う。

## 振る舞い

### 所属と権限

BOT は既存の利用者レコードに `account_kind=bot` と `bot_tenant_id` を持つ。
所属、役割、プロジェクトの明示所属、PAT のスコープ判定を既存の仕組みと共有する。
BOT の役割は Member 相当まで（テナントでもプロジェクトでも Member か Viewer）に縛る。
BOT を Admin で作る、BOT を Admin に上げる、BOT を Admin でテナントやプロジェクトに加える操作は 400（`bot-role-too-strong`）で断る。
自動化に Admin の力が要るようになったら、この上限を緩める余地を残している。
BOT 自身の PAT では BOT 管理や PAT 発行を行えない。
BOT は個人用プロジェクト（My Tasks の Inbox）を持たない。個人用プロジェクトのエンドポイントは BOT には 404 を返す。
これらの操作には人のセッション認証が必要になる。

BOT を別のテナントのメンバーやプロジェクトのゲストに追加する操作、メール招待、招待の承諾は拒否する。
所属を取り除く操作の代わりに、BOT の停止を使う。
BOT のパスワード、パスキー、OAuth、TOTP、端末認証、対話用セッションは利用できない。

### PAT の管理

PAT は発行時に一度だけ表示する。
管理画面を閉じると平文の値を消し、一覧では末尾 4 文字だけを表示する。
PAT の有効期限は必須で、発行時点から最大 365 日とする。
画面は端末の時計から期限を作るので、上限には 5 分の猶予を足す。
期限、スコープ、許可プロジェクトを絞ることで、漏えいした鍵の有効範囲を小さくする。

BOT を停止すると、その BOT の PAT をすべて取り消す。
再開しても取り消した PAT は復活せず、新しい鍵を発行する必要がある。
利用者レコードは残すため、過去のコメント、担当、操作履歴の投稿者を維持できる。

### 表示

担当者、担当者の候補、コメント投稿者、操作履歴、所属一覧に BOT の表示を付ける。
BOT はメンションの候補とコメントの投稿者にもなれる。

### メール

メンションを含む通知データは既存の通知機構で扱うが、BOT にメールは配信しない。
メールアドレスは `<利用者 UUID>@bots.task.invalid` を内部で割り当てる。
この値は BOT の識別用で、受信箱を持たない。
メール送信前に BOT 専用アドレスを除外し、通知メールでは利用者の種別も検査する。

### 漏えいした PAT の範囲

PAT を取得した第三者は、その BOT の所属と役割、トークンのスコープ、有効期限、許可プロジェクトの交差で許された API 操作を行える。
書き込み権限を与えた場合は、タスクやコメントなどのデータを変更できる。
BOT の役割は Member 相当までなので、漏えいした PAT でメンバーの追加や役割の変更（人への権限の委任）は行えない。
必要なスコープに絞り、プロジェクト制限を併用する。

BOT の PAT から新しい PAT や BOT を発行することはできない。
人のセッションや端末トークンへ交換することもできない。
漏えい時は PAT を取り消すか BOT を停止し、関連する操作履歴を確認する。

## データ

`users` に足した列は次のとおりである。

| 列 | 型 | 制約 | 説明 |
|---|---|---|---|
| `account_kind` | text | NOT NULL、既定値は `human` | 利用者の種別。`human` か `bot` |
| `bot_tenant_id` | uuid | `tenants` への外部キー。テナントを消すと BOT も消える | BOT の持ち主のテナント。人では空 |

BOT の行は CHECK 制約で縛る。宛先は `<利用者 UUID>@bots.task.invalid` に限り、パスワードと TOTP を持たず、プラットフォーム管理者にならない。

列の定義は [m20261106000000_tenant_bots.rs](https://github.com/koyori-app/task/blob/main/apps/backend/migration/src/m20261106000000_tenant_bots.rs) にある。

## API

BOT の管理のエンドポイントは次のとおりである。

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/v1/tenants/{tenant_id}/bots` | BOT の一覧 |
| POST | `/v1/tenants/{tenant_id}/bots` | BOT の作成 |
| PATCH | `/v1/tenants/{tenant_id}/bots/{bot_id}` | BOT の停止と再開 |
| GET | `/v1/tenants/{tenant_id}/bots/{bot_id}/tokens` | PAT の一覧 |
| POST | `/v1/tenants/{tenant_id}/bots/{bot_id}/tokens` | PAT の発行 |
| DELETE | `/v1/tenants/{tenant_id}/bots/{bot_id}/tokens/{token_id}` | PAT の取り消し |

`GET /v1/personal_tokens/me` と、利用者を返す応答は `account_kind` を含む。
BOT に Admin の役割を渡す要求は 400 を返し、`message` は `bot-role-too-strong` になる。

## 認可

| 操作 | 誰が | スコープ |
|---|---|---|
| BOT の一覧、作成、停止、再開 | テナントのオーナーと Admin の人。セッション認証に限る | PAT では使えない |
| BOT の PAT の一覧、発行、取り消し | テナントのオーナーと Admin の人。セッション認証に限る | PAT では使えない |
| BOT の PAT による API の利用 | BOT | PAT のスコープとプロジェクト制限の範囲 |

テナントが 2FA を強制していれば、2FA を満たさない Admin は BOT の管理のエンドポイントで 403 になる。
BOT の PAT は 2FA の強制の対象から外す。

## 画面

| 項目 | 値 |
|---|---|
| URL | `/{tenant}/settings/members` |
| 入口 | テナントの設定のメンバー |

BOT の欄はテナントのオーナーと Admin にだけ表示する。
欄では BOT の一覧、作成、停止と再開、PAT の発行と取り消しを行う。
BOT の役割は Member か Viewer から選ぶ。

## 未実装と既知の制限

- メンションのチップには BOT の表示を付けていない。チップは Vue の部品でなく CSS で描くため

## 決定の記録

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-11-04 | BOT の宛先を `<利用者 UUID>@bots.task.invalid` にし、メールアドレスを任意にしない | 宛先を読む箇所が広く、届かない宛先なら型を変えずに送信の一箇所で止められる |
| 2026-11-04 | PAT の有効期限を必須にし、上限を 365 日とする | BOT の鍵は人が日々見ない所に置かれ、漏れても気づきにくい |
| 2026-11-04 | BOT は削除せず、停止だけにする | コメントや担当の投稿者を残す |
| 2026-11-05 | BOT の役割を Member 相当までに縛る | Admin の BOT の PAT から人へ権限を委ねられるため |
| 2026-11-05 | BOT は個人用プロジェクトを持たない | 個人用プロジェクトの Admin として、テナントの外の人をゲストに加えられるため |
| 2026-11-05 | BOT の PAT をテナントの 2FA の強制の対象から外す | BOT は TOTP もパスキーも持てず、PAT の発行は 2FA を満たした Admin に限るため |
