# テナントの BOT アカウント

テナント Admin は、設定のメンバー画面から自動化用の BOT を作成できる。
BOT は作成元の一つのテナントだけに属し、PAT で API と既存 CLI を利用する。
管理者は BOT の作成、停止、再開、PAT の発行と取り消しを行える。

## 所属と権限

BOT は既存の利用者レコードに `account_kind=bot` と `bot_tenant_id` を持つ。
所属、役割、プロジェクトの明示所属、PAT のスコープ判定を既存の仕組みと共有する。
BOT の役割は Member 相当まで（テナントでもプロジェクトでも Member か Viewer）に縛る。
BOT を Admin で作る、BOT を Admin に上げる、BOT を Admin でテナントやプロジェクトに加える操作は 400（`bot-role-too-strong`）で断る。
自動化に Admin の力が要るようになったら、この上限を緩める余地を残している。
BOT 自身の PAT では BOT 管理や PAT 発行を行えない。
BOT は個人用プロジェクト（My Tasks の Inbox）を持たない。個人用プロジェクトの口は BOT には 404 を返す。
これらの操作には人のセッション認証が必要になる。

BOT を別のテナントのメンバーやプロジェクトの客分に追加する操作、メール招待、招待の承諾は拒否する。
所属を取り除く操作の代わりに、BOT の停止を使う。
BOT のパスワード、パスキー、OAuth、TOTP、端末認証、対話用セッションは利用できない。

## PAT の管理

PAT は発行時に一度だけ表示する。
管理画面を閉じると平文の値を消し、一覧では末尾 4 文字だけを表示する。
PAT の有効期限は必須で、発行時点から最大 365 日とする。
期限、スコープ、許可プロジェクトを絞ることで、漏えいした鍵の有効範囲を小さくする。

BOT を停止すると、その BOT の PAT をすべて取り消す。
再開しても取り消した PAT は復活せず、新しい鍵を発行する必要がある。
利用者レコードは残すため、過去のコメント、担当、操作履歴の投稿者を維持できる。

## 表示とメール

担当者、コメント投稿者、操作履歴、所属一覧に BOT の表示を付ける。
BOT はメンションの候補とコメントの投稿者にもなれる。
メンションを含む通知データは既存の通知機構で扱うが、BOT にメールは配信しない。

メールアドレスは `<利用者 UUID>@bots.task.invalid` を内部で割り当てる。
この値は BOT の識別用で、受信箱を持たない。
メール送信前に BOT 専用アドレスを除外し、通知メールでは利用者の種別も検査する。

## 漏えいした PAT の範囲

PAT を取得した第三者は、その BOT の所属と役割、トークンのスコープ、有効期限、許可プロジェクトの交差で許された API 操作を行える。
書き込み権限を与えた場合は、タスクやコメントなどのデータを変更できる。
BOT の役割は Member 相当までなので、漏えいした PAT でメンバーの追加や役割の変更（人への権限の委任）は行えない。
必要なスコープに絞り、プロジェクト制限を併用する。

BOT の PAT から新しい PAT や BOT を発行することはできない。
人のセッションや端末トークンへ交換することもできない。
漏えい時は PAT を取り消すか BOT を停止し、関連する操作履歴を確認する。
