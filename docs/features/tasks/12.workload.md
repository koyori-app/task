# 山積み・手動の山崩し 仕様書

> ステータス: **Draft** / 作成日: 2026-10-19
> **依存: [スケジュール](/features/tasks/schedule)（schedule API・カレンダー画面）・[コア](/features/tasks/core)（`planned_start_on` / `estimated_minutes`）・[作業時間追跡](/features/tasks/time-tracking)（`time_logs`）**

---

## 1. 概要

テナントカレンダーに、メンバーごと・日ごとの作業量を棒（山）で出す。積む量は見積ではなく残工数（見積 − 実績）とし、複数の担当者がいるタスクは担当者で分ける。カレンダー上で帯の始点を動かして開始予定日を変えられるようにし、山を見ながら手で崩せるようにする。

対象外（別仕様）:

- 人ごとの稼働時間・テナントの休日。上限は現行どおり 1 日 6h・土日非稼働・祝日なしの固定
- 自動の山崩し（並べ替えの探索）
- 過去の日に実績を描くこと（§9）

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| 山積み | メンバーごと・日ごとに積んだ作業時間の棒 |
| 残工数 | `max(estimated_minutes − logged_minutes, 0)`。タスク単位 |
| 配分期間 | 残工数を均等に割って積む平日の集合（§3.2） |
| 上限 | 1 日に積める時間。固定 6h |
| 超過 | ある日の山が上限を超えた状態 |
| 山崩し | 開始予定日を変えて山の形を変える操作 |

---

## 3. 計算規則

計算はすべてクライアント側で行う（現行の `見積/日` と同じ）。サーバーは §4 の 1 項目と 1 引数を足すだけ。

### 3.1 積む対象

次を**すべて**満たすタスク:

- アーカイブ済み・削除済みでない（schedule API が返すもの）
- 完了ステータス（`is_done_state = true`）でない
- `planned_start_on` がある
- Soft 締切がある（Hard 締切だけのタスクは積まない。現行どおり）
- `estimated_minutes` があり、残工数が 1 分以上

### 3.2 配分期間

```
始点 = max(今日, min(planned_start_on, Soft 締切の日付))
終点 = max(planned_start_on, Soft 締切の日付)
配分期間 = 始点〜終点（両端含む）の平日
```

- 「今日」は表示タイムゾーン（ブラウザ）での日付。Soft 締切の日付への落とし方はスケジュール §3 と同じ
- 配分期間が空（締切を過ぎている、または始点〜終点が土日だけ）のときは**今日 1 日に全部積む**。締切超過の残工数を消さない
- 開始予定日が締切より後のタスクは、スケジュール §3 と同じく両端を入れ替えて扱う

### 3.3 1 人あたり・1 日あたりの時間

```
1 日あたり = 残工数 / 60 ÷ 配分期間の日数
1 人あたり = 1 日あたり ÷ 担当者数
```

- 担当者数は `task_assignees` の件数。`role` は見ない（`primary` と `assignee` を区別しない）
- 担当者がいないタスクは積まない（「担当者なし」行に山は出さない）

### 3.4 超過

メンバーの 1 日の合計が上限（6h）を**超えた**日を超過とする。ちょうど 6h は超過でない（現行どおり）。

### 3.5 現行からの変更点

| 項目 | 現行（スケジュール §5） | 本仕様 |
|---|---|---|
| 積む量 | `estimated_minutes` | 残工数 |
| 期間 | 開始予定日〜Soft 締切 | 今日〜Soft 締切に切り詰め |
| 過去の日 | 積む | 積まない |
| 締切超過 | 期間なし → 積まない | 今日に全部 |
| 担当者 | `primary` だけに全額 | 全担当者で均等割り |

## 4. API

### 4.1 schedule API の変更

`GET /v1/tenants/{tenant_id}/schedule` の `tasks[]` に 1 項目、クエリに 1 引数足す。

| フィールド | 型 | 内容 |
|---|---|---|
| `logged_minutes` | int | そのタスクの `time_logs.logged_minutes` の合計。担当者以外の記録も含む。記録が無ければ 0 |

- 集計は SQL 側（`LEFT JOIN LATERAL` または相関サブクエリ）。Rust 側で `time_logs` を全件取って足さない
- 定義は `GET /tasks/{id}/time-logs/summary` の `actual_minutes` と同じ。乖離させない
- `ScheduleTask` は CLI が読むので `Deserialize` を維持する

| クエリ | 内容 |
|---|---|
| `include_overdue` | 既定 false。true なら締切超過のタスク（Soft 締切・開始予定日・見積があり、終点が `from` より前で未完了のもの）も返す。§3.1 で積めないものは返さない（締切超過の backlog を毎回全部取らない） |

- 表示期間より前に締切を過ぎたタスクは期間判定で返らず、§3.2 の「今日に全部積む」が効かない。画面は表示期間が今日を含むときにだけ `include_overdue=true` を付ける
- 締切超過のタスクは期間外なので帯には出ず、山（今日の棒）にだけ効く

新しいエンドポイントは無い。山崩しは既存の `PUT /v1/tenants/{tenant_id}/projects/{project_id}/tasks/{id}` に `planned_start_on` だけを載せて送る。

### 4.2 認可

変更なし。schedule API は `read:task`、山崩しの更新はタスク更新と同じ（`write:task` + プロジェクトの書き込み権限）。カレンダーに見えていても更新できないタスクはあり、その場合は 403 を画面で処理する（§5.3）。

## 5. 画面（`/{tenant}/calendar`）

### 5.1 山の表示

- 各メンバー行の最上段（現行の `見積/日` の数字がある段）を、棒 + 数字にする。棒の高さは上限 6h を段の高さとする比率。超過分は上限の線を越えて描き、警告色
- 棒にマウスを乗せると、その日のタスク内訳（`KEY-N`、1 人あたりの時間）を出す
- 読み上げ文言は現行を踏襲: `2026-10-14 の見積 7h（上限 6h を超過）`。「見積」は「残り」に改める
- 「担当者なし」行には棒を出さない
- メンバー・プロジェクトの絞り込みは現行どおりクライアント側。絞り込んでも**山は絞り込み前の全タスクで計算する**（プロジェクトで絞ったときに他プロジェクトの負荷が消えると超過を見落とす）

### 5.2 手動の山崩し

- 帯（開始予定日のあるタスク）を横にドラッグすると、**始点だけ**が日単位で動く。終点は締切なので動かない
- キーボード: 帯にフォーカスして `←` / `→` で 1 日ずつ動かし、`Enter` で確定、`Esc` で取消
- ドラッグ中は山をローカルで再計算して追従させる（確定前に結果が見える）
- 確定時に `planned_start_on` だけを送る。成功したら schedule のクエリを無効化して再取得する
- 新しい開始予定日が Soft 締切の日付より後になる位置へは置けない（タスク作成ダイアログと同じ警告。サーバーは検証しないので画面で止める）
- 点（開始予定日の無いタスク）は動かせない。開始予定日の設定はタスク詳細から行う
- 変更は既存の `planned_start_changed` 履歴に記録される（追加実装なし）

### 5.3 失敗時

- 403 / 404: 帯を元の位置に戻し、「このタスクは変更できません」を出す
- その他の失敗: 帯を元の位置に戻し、エラー内容を出す
- 楽観更新はしない（ドラッグ中の追従は見た目だけで、確定前の状態に戻せる）

## 9. 決定事項

| 項目 | 決定内容 |
|---|---|
| 積む量 | 残工数。見積の均等割りは「残り何時間か」の近似にすぎず、作業記録があるなら差し替える |
| `logged_minutes` の範囲 | 担当者以外の記録も含むタスク単位の合計。残工数はタスクの性質であり、サマリー API の `actual_minutes` と定義を揃える |
| 過去の日 | 積まない。過去に実績を描くには日別の記録が要り、schedule API の応答が膨らむ。別仕様に送る |
| 締切超過の残工数 | 今日に全部積む。消すと超過が見えなくなる。表示期間より前に締切を過ぎたものは schedule API が返さないため、`include_overdue` で取る（取得期間を広げる案は 92 日の上限で漏れが残る） |
| 開始予定日の無いタスク | 積まない。今日から積むと未着手の全タスクが今日に乗り、山が意味を失う。開始予定日は「いつやるか」の意思表示として入れてもらう |
| 担当者の分け方 | 均等割り。比率を持つには `task_assignees` に列が要り、入力の手間に見合う根拠がまだ無い。`role` の正規化もしない |
| 上限 | 6h 固定を維持。人別・休日は別仕様 |
| 山崩しで動かすもの | 開始予定日だけ。締切をカレンダーから動かすと通知や期限超過の判定に波及する |
| 計算の置き場 | クライアント。92 日・500 件の上限内で足り、サーバーに集計エンドポイントを足す理由がまだ無い |
| 絞り込みと山 | 山は絞り込み前の全タスクで計算する。見えていないプロジェクトの負荷を落とすと超過を見落とす |
