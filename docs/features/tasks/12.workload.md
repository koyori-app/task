## 1. 概要

テナントカレンダーに、メンバーごと・日ごとの作業量を棒（山）で出す機能である。積む量は見積ではなく残工数（見積 − 実績）で、複数の担当者がいるタスクは担当者で分ける。カレンダー上で帯の始点を動かして開始予定日を変えられるので、山を見ながら手で崩せる。

未実装で、この機能の対象外としているものは次のとおりである。

- 人ごとの稼働時間・テナントの休日。上限は 1 日 6h・土日非稼働・祝日なしの固定である
- 自動の山崩し（並べ替えの探索）
- 過去の日に実績を描くこと（§9）

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| 山積み | メンバーごと・日ごとに積んだ作業時間の棒 |
| 残工数 | `max(estimated_minutes − logged_minutes, 0)`。タスク単位 |
| 配分期間 | 残工数を均等に割って積む平日の集合（§3.2） |
| 上限 | 1 日に積める時間。固定 6h |
| 超過 | ある日の山が上限を超えた状態 |
| 山崩し | 開始予定日を変えて山の形を変える操作 |

---

## 3. 計算規則

計算はすべてクライアント側（`lib/calendar/load.ts`）で行う。サーバーは §4 の 1 項目と 1 引数で材料を渡すだけである。

### 3.1 積む対象

次を**すべて**満たすタスク:

- アーカイブ済み・削除済みでない（schedule API が返すもの）
- 完了ステータス（`is_done_state = true`）でない
- `planned_start_on` がある
- Soft 締切がある（Hard 締切だけのタスクは積まない）
- `estimated_minutes` があり、残工数が 1 分以上

### 3.2 配分期間

```
始点 = max(今日, min(planned_start_on, Soft 締切の日付))
終点 = max(planned_start_on, Soft 締切の日付)
配分期間 = 始点〜終点（両端含む）の平日
```

- 「今日」は表示タイムゾーン（ブラウザ）での日付。Soft 締切の日付への落とし方はスケジュール §3 と同じ
- 配分期間が空のときは 1 日に全部積む。締切を過ぎているなら**今日**（締切超過の残工数を消さない）、始点〜終点が土日だけなら**その直前の平日**（今日より前なら今日）
- 開始予定日が締切より後のタスクは、スケジュール §3 と同じく両端を入れ替えて扱う

### 3.3 1 人あたり・1 日あたりの時間

```
1 日あたり = 残工数 / 60 ÷ 配分期間の日数
1 人あたり = 1 日あたり ÷ 担当者数
```

- 担当者数は `task_assignees` の件数。`role` は見ない（`primary` と `assignee` を区別しない）
- 担当者がいないタスクは積まない（「担当者なし」行に山は出さない）

### 3.4 超過

メンバーの 1 日の合計が上限（6h）を**超えた**日を超過とする。ちょうど 6h は超過でない。

### 3.5 見積をそのまま積む規則との違い

この規則は、見積を期間で均等に割って積む最初の規則を置き換えたものである。`load.test.ts` はこの表の各行を確かめる。

| 項目 | 見積をそのまま積む規則 | 現在の規則 |
|---|---|---|
| 積む量 | `estimated_minutes` | 残工数 |
| 期間 | 開始予定日〜Soft 締切 | 今日〜Soft 締切に切り詰め |
| 過去の日 | 積む | 積まない |
| 締切超過 | 期間なし → 積まない | 今日に全部 |
| 担当者 | `primary` だけに全額 | 全担当者で均等割り |

## 4. API

### 4.1 schedule API の項目

`GET /v1/tenants/{tenant_id}/schedule` の `tasks[]` の項目とクエリのうち、山積みのためにあるものは次のとおりである。

| フィールド | 型 | 内容 |
|---|---|---|
| `logged_minutes` | int | そのタスクの `time_logs.logged_minutes` の合計。担当者以外の記録も含む。記録が無ければ 0 |

- 集計は SQL 側の相関サブクエリで行う。Rust 側で `time_logs` を全件取って足さない
- 定義は `GET /tasks/{id}/time-logs/summary` の `actual_minutes` と同じ。乖離させない
- `ScheduleTask` は CLI が読むので `Deserialize` を維持する

| クエリ | 内容 |
|---|---|
| `include_overdue` | 既定 false。true なら締切超過のタスク（Soft 締切・開始予定日・見積があり、終点が `from` より前で未完了のもの）も返す。§3.1 で積めないものは返さない（締切超過の backlog を毎回全部取らない） |

- 表示期間より前に締切を過ぎたタスクは期間判定で返らないので、このクエリが無いと §3.2 の「今日に全部積む」の材料が揃わない。画面は表示期間が今日を含むときにだけ `include_overdue=true` を付ける
- 締切超過のタスクは期間外なので帯には出ず、山（今日の棒）にだけ積む

専用のエンドポイントは無い。山崩しは `PUT /v1/tenants/{tenant_id}/projects/{project_id}/tasks/{id}` に `planned_start_on` だけを載せて送る。

### 4.2 認可

schedule API は `read:task`、山崩しの更新はタスク更新と同じ（`write:task` + プロジェクトの書き込み権限）である。カレンダーに見えていても更新できないタスクはあり、その場合は 403 を画面で処理する（§5.3）。

## 5. 画面（`/{tenant}/calendar`）

### 5.1 山の表示

- 各メンバー行の最上段に、棒と数字を出す。棒の高さは上限 6h を段の高さとする比率である。超過分は上限の線を越えて描き、警告色にする
- 棒にマウスを乗せると、その日のタスク内訳（`KEY-N`、1 人あたりの時間）を出す
- 読み上げ文言は `2026-10-14 の残り 7h（上限 6h を超過）` の形である
- 「担当者なし」行には棒を出さない
- メンバー・プロジェクトの絞り込みはクライアント側である。絞り込んでも**山は絞り込み前の全タスクで計算する**（プロジェクトで絞ったときに他プロジェクトの負荷が消えると超過を見落とす）

### 5.2 手動の山崩し

- 帯（開始予定日のあるタスク）を横にドラッグすると、**始点だけ**が日単位で動く。終点は締切なので動かない。タッチの横スワイプはスクロールに使うので、タッチではキーボード操作かタスク詳細で変える
- キーボード: 帯にフォーカスして `←` / `→` で 1 日ずつ動かし、`Enter` で確定、`Esc` で取消
- ドラッグ中は山をローカルで再計算して追従させる（確定前に結果が見える）
- 確定時に `planned_start_on` だけを送る。成功したら schedule のクエリを無効化して再取得する
- 新しい開始予定日が Soft 締切の日付より後になる位置へは置けない（タスク作成ダイアログと同じ警告。サーバーは検証しないので画面で止める）。締切の日付への落とし方は帯の終点と同じくスケジュール §3（表示タイムゾーン）
- 開始予定日の無いタスク（締切の点と Soft〜Hard の帯）は動かせない。開始予定日の設定はタスク詳細から行う
- 開始予定日を元の位置より表示範囲の外へは動かさず、帯が範囲から外れる位置にも置かない（帯が消えると確定も取消もできない）
- 確定前の移動は、フォーカスを外す・別の帯をドラッグする・ドラッグが途中で切れると取り消す。送信中は確定も取消も受け付けない
- 変更は `planned_start_changed` 履歴に記録される

### 5.3 失敗時

- 403 / 404: 帯を元の位置に戻し、「このタスクは変更できません」を出す
- その他の失敗: 帯を元の位置に戻し、エラー内容を出す
- 楽観更新はしない（ドラッグ中の追従は見た目だけで、確定前の状態に戻せる）

## 6. 実装の配置

| 内容 | 場所 |
|---|---|
| `logged_minutes` と `include_overdue` | `handler::handlers::schedule`（`openapi.json` にも反映） |
| 山の計算規則 | `lib/calendar/load.ts`（§3） |
| 棒の表示とドラッグ・キーボードの操作 | `components/calendar/CalendarTimeline.vue` |
| `today` の受け渡し・`include_overdue` の付与・期間外タスクの間引き | `pages/@tenant/calendar/+Page.vue` |

棒の見た目と数字の規則を分けて置いている。規則を変えると数字が変わるので、見た目の変更と混ぜるとテストで切り分けられないためである。

## 7. テスト

- backend 統合テスト（`schedule_integration.rs`）: 2 人の作業記録を持つタスクの `logged_minutes` が合計になること、記録の無いタスクが 0 であること、担当者でない人の記録も含むこと
- `load.test.ts`: §3.5 の各行を 1 ケースずつ。残工数 0 は積まれない、締切超過は今日に全部、担当者 2 人で半分、`primary` と `assignee` が同額、開始予定日の無いタスクは積まれない
- `CalendarTimeline.test.ts`: 超過の棒が警告色、絞り込み後も山が変わらない、点はドラッグできない、締切より後へドロップすると送信しない、403 で元に戻る

## 9. 決定事項

| 項目 | 決定内容 |
|---|---|
| 積む量 | 残工数。見積の均等割りは「残り何時間か」の近似にすぎないので、作業記録の分を引く |
| `logged_minutes` の範囲 | 担当者以外の記録も含むタスク単位の合計。残工数はタスクの性質であり、サマリー API の `actual_minutes` と定義を揃える |
| 過去の日 | 積まない。過去に実績を描くには日別の記録が要り、schedule API の応答が膨らむ。過去の日の実績の表示は未実装である |
| 締切超過の残工数 | 今日に全部積む。消すと超過が見えなくなる。表示期間より前に締切を過ぎたものは schedule API が返さないため、`include_overdue` で取る（取得期間を広げる案は 92 日の上限で漏れが残る） |
| 土日だけの期間 | 直前の平日に積む。今日に積むと、表示期間より後の土日のタスク（schedule API が返さない）だけが漏れ、見ている週によって今日の山が変わる。表示期間は月曜始まりなので、直前の平日は期間内か期間より後に収まる |
| 開始予定日の無いタスク | 積まない。今日から積むと未着手の全タスクが今日に乗り、山が意味を失う。開始予定日は「いつやるか」の意思表示として入れてもらう |
| 担当者の分け方 | 均等割り。比率を持つには `task_assignees` に列が要り、入力の手間に見合う根拠がまだ無い。`role` の正規化もしない |
| 上限 | 6h 固定を維持。人別・休日は別仕様 |
| 山崩しで動かすもの | 開始予定日だけ。締切をカレンダーから動かすと通知や期限超過の判定に波及する |
| 計算の置き場 | クライアント。92 日・500 件の上限内で足り、サーバーに集計エンドポイントを足す理由がまだ無い |
| 絞り込みと山 | 山は絞り込み前の全タスクで計算する。見えていないプロジェクトの負荷を落とすと超過を見落とす |
