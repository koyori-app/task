# コメントのメンションのクリップボード形式

> ステータス: **web は実装済み** / desktop・iOS・Android は未実装（下の「残件」）
> 親: [コメント・アクティビティ §3 @メンション処理](/features/tasks/collaboration)

コメントまたはタスクの説明文の入力欄で札（`@名` の表示）を含む文をコピー・切り取りし、task の入力欄（同じ欄・別のコメント・別のタスク・
別の端末の app）へ貼ると、札のまま（本文が `<@利用者ID>`）に戻る。task の外のアプリへ貼ると `@今の名` の素の文字になる。
この文書は、その往復を **web・desktop・iOS・Android の全部が同じく読み書きする**ための決まりを定める。

---

## 1. 形式

クリップボードには、一つの項目に **二つの表現**を載せる。独自の MIME 型は足さない
（web の中だけで閉じる形式——Chromium の web custom format、`DataTransfer` の独自の型——に頼ると、
OS のクリップボードを通る native の app が読めぬため）。

| MIME 型 | 中身 |
|---------|------|
| `text/plain` | 札を `@今の名` に直した文。印（`<@`）も id も含まぬ |
| `text/html` | 同じ文を、札の要素つきの HTML 断片にした物 |

### 1.1 `text/html` の札の要素

```html
<div>見て <span data-task-mention="1" data-user-id="11111111-1111-4111-8111-111111111111">@alice</span> 確認お願いします<br>次の行</div>
```

| 名 | 意味 |
|----|------|
| 要素 `span` | 札を表す。中身は札の表示字（`@今の名`）。HTML が読める別のアプリは、この字だけを拾う |
| 属性 `data-task-mention` | 札の印であり**版**。値は `1`（この文書の形式） |
| 属性 `data-user-id` | 利用者の id（ハイフン付き UUID、36 字） |
| 要素 `br` | 改行 |
| 外側の `div` | 断片の根。ほかの要素・属性は付けぬ |

表示字（`@今の名`）はコピーした時点の名であり、貼り付け側は**使わない**（貼り付けた後の札の名は
その場の対応表から引く）。表示字の特殊字（`& < > "`）は HTML の実体参照にする。

### 1.2 書く側の決まり

1. 選んだ範囲の印 `<@id>` を、札の要素に変える。印でない地の文は、実体参照にしたうえで改行を `br` にして並べる
2. `text/plain` には、印を `@今の名` に直した文を置く（名が引けぬ者・退会した者・プロジェクトの外の者は、
   画面の札と同じ `@（不明な利用者）`・`@（退会した利用者）`・`@（このプロジェクトの外の利用者）`）
3. 切り取りは、書いたあとに範囲を消す
4. 利用者の id は秘密ではない（画面では見た目のために隠しておるだけ）。ただし**名前は本文に載せぬ**
   のと同じく、`outside` の者の名前を `text/plain` / 表示字に書いてはならぬ（上の 2 の字を使う）

### 1.3 読む側の決まり

貼り付けでは、`text/html` を次の順で検める。**一つでも外れたら、その札は札にせず、字（要素の中身）だけ拾う**。
札が一つも残らなければ、`text/html` は無かった物として扱い、従来どおり `text/plain` を素の文字として入れる。

1. `data-task-mention` を持つ要素だけを札の候補とする（属性が無い要素の `data-user-id` は読まぬ）
2. `data-task-mention` の値が**知っておる版**（今は `1`）か。知らぬ値は札にせず、素の字に倒す
3. `data-user-id` が印の形（`[0-9a-fA-F]{8}-…-[0-9a-fA-F]{12}` の 36 字）か。壊れた id は札にしない
4. 通った札は小文字の id にして `<@id>` に戻し、札でない字はそのまま繋ぐ。`br` と段落の境（`div`・`p`・`li`）は改行

読み取るのは字と上の二つの属性だけで、HTML の他の要素・属性・`script`・`style` は使わぬ（実行も描画もしない）。

### 1.4 守り（権限の道が増えぬ理由）

- 貼られた `<@id>` が**通知を撃つ**かは、送信時に backend が判じる。宛先の境（プロジェクトに入れる者とテナント owner）は
  従来どおりで、境の外・在らぬ id は通知せずに保存する。clipboard から来た id でも同じ
- 札の**表示**（`member`・`outside`・`gone`）は、貼った先のコメント API が返す対応表に従う。
  clipboard が運ぶ名前は使わぬので、他人の環境から来た clipboard で `outside` の者の名前を引き出すことはできぬ
- task の外から来た HTML に紛れた id は、`data-task-mention="1"` が付いておらねば札にならぬ。付いておっても
  上の 3 の形でなければ札にならぬ。付けて偽った場合も、効くのは「その id を本文に入れる」ことだけで、
  手で `<@id>` と打てば同じ結果になる（新しい権限の道は生まれぬ）

## 2. platform ごとの写し方

native の clipboard は、どれも「一つの項目に複数の表現を載せ、型の名で引く」作りである。
`text/plain` と `text/html` は次の名に写る。

| platform | `text/plain` | `text/html` | 注記 |
|----------|-------------|------------|------|
| web（Chromium・Firefox・Safari） | `clipboardData.setData('text/plain', …)` | `setData('text/html', …)` | 貼り付けは `paste` event の `getData('text/html')` |
| Windows | `CF_UNICODETEXT` | 登録名 `HTML Format`（`CF_HTML`） | UTF-8。`Version`・`StartHTML`・`EndHTML`・`StartFragment`・`EndFragment` の byte offset を持つ頭と、断片を挟む `<!--StartFragment-->`・`<!--EndFragment-->` が要る。**断片の中が 1.1 の `div`** |
| macOS | `NSPasteboard.PasteboardType.string` | `NSPasteboard.PasteboardType.html`（`public.html`） | 一つの `NSPasteboardItem` に両方の表現を載せる |
| iOS | `public.utf8-plain-text`（`UTType.plainText`） | `public.html`（`UTType.html`） | `UIPasteboard.setItems` で一つの項目に両方を載せる |
| Android | `ClipData` の `text` | `ClipData.newHtmlText(label, text, htmlText)` の `htmlText` | `text` は HTML を読めぬ受け手のための素の字（`@今の名`）。MIME 型は `text/html` と `text/plain` |

native の app は、読む側の決まり（1.3）を**そのまま**使う。HTML を DOM に直せぬ環境でも、
`data-task-mention="1"` と `data-user-id="…"` を持つ `span` の二つの属性だけが取れれば足りる。

### 2.1 出所と、確かめた範囲

- web の `clipboardData` と `text/html`: MDN「ClipboardEvent: clipboardData」
- Windows の `HTML Format`（`CF_HTML`）: Microsoft Learn「HTML Clipboard Format」
- iOS・macOS の pasteboard が一つの項目に複数の表現を型（UTI）で持つこと: Apple「Pasteboard Concepts」、
  `UIPasteboard.setItems(_:options:)`
- Android の `ClipData.newHtmlText`（`text` を HTML を読めぬ受け手の素の字として必須）: Android Developers「ClipData」
- 実測（Linux の Playwright 1.63）: Chromium 153・Firefox 155・WebKit 26.6 のそれぞれで、実際のキー操作の copy → paste で
  `text/html` の `data-task-mention`・`data-user-id` が欠けずに届き、`text/plain` は `@今の名` のまま届く。
  Windows・macOS・iOS・Android の native と、macOS・iOS の Safari の実機は**確かめておらぬ**
  （特に、native の app が `text/html` を貼る時に `data-*` 属性を落とさぬかは、実装の段で確かめる）

## 3. 例

選んだ文（本文が `見て <@11111111-1111-4111-8111-111111111111> 確認` の時）:

```text
text/plain: 見て @alice 確認
text/html : <div>見て <span data-task-mention="1" data-user-id="11111111-1111-4111-8111-111111111111">@alice</span> 確認</div>
```

読む側が出す本文: `見て <@11111111-1111-4111-8111-111111111111> 確認`

読む側が札にせぬ例（いずれも字だけ入る）:

```html
<span data-user-id="11111111-1111-4111-8111-111111111111">@x</span>
<span data-task-mention="2" data-user-id="11111111-1111-4111-8111-111111111111">@x</span>
<span data-task-mention="1" data-user-id="not-a-uuid">@x</span>
```

## 4. 残件

- **desktop の app**・**iOS の app**・**Android の app** の読み書きは未実装（この文書の形式を、上の写し方で実装する）。
  この repo には desktop・mobile の app の作りは無い（web の frontend と backend のみ）
- 版 `2` 以降の拡張（例: 表示字の持ち方の変更）。読む側は知らぬ版を素の字に倒すので、先に書く側を新しくしても
  古い読む側は壊れぬ
- コメントを Markdown として描く段（本文の KFM 描画）を入れる時は、クリップボードの `text/plain` を `@今の名` のまま保つ
