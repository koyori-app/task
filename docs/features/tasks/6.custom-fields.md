## 1. データモデル

### 1.1 `project_custom_fields`

```rust
pub struct Model {
    pub id: Uuid,
    pub project_id: Uuid,
    pub name: String,
    pub field_type: CustomFieldType,  // text | number | select | date | url | checkbox
    pub options: Option<Value>,       // select 型の選択肢 JSON
    pub is_required: bool,
    pub position: i16,
    pub created_at: DateTimeUtc,
}
```

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| `id` | UUID | PK | |
| `project_id` | UUID | NOT NULL, FK→projects CASCADE | |
| `name` | VARCHAR(100) | NOT NULL | 例: "Story Points", "バージョン" |
| `field_type` | VARCHAR | NOT NULL CHECK | `text` / `number` / `select` / `date` / `url` / `checkbox` |
| `options` | JSONB | NULLABLE | `select` 型のみ使用: `[{"label":"S","value":"s"},...]` |
| `is_required` | BOOLEAN | NOT NULL DEFAULT false | |
| `position` | SMALLINT | NOT NULL | 表示順 |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| — | — | UNIQUE(project_id, name) | |

### 1.2 `task_custom_field_values`

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| `task_id` | UUID | NOT NULL, FK→tasks CASCADE | |
| `field_id` | UUID | NOT NULL, FK→project_custom_fields CASCADE | |
| `value` | TEXT | NULLABLE | 全型を文字列で保持する。数値・日付はアプリ層で検証する |
| — | — | PRIMARY KEY(task_id, field_id) | |

型ごとの値フォーマット:

| `field_type` | `value` の形式 | 例 |
|-------------|--------------|-----|
| `text` | 任意文字列 | `"メモ"` |
| `number` | 有限の数値として読める文字列 | `"5"` |
| `select` | `options` の `value` のいずれか | `"s"` |
| `date` | `YYYY-MM-DD` | `"2026-06-01"` |
| `url` | `http` または `https` の URL | `"https://..."` |
| `checkbox` | `"true"` / `"false"` | `"true"` |

形式に合わない値は 400 になる。

## 2. マイグレーション

```sql
CREATE TABLE project_custom_fields (
    id UUID PRIMARY KEY,
    project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,
    field_type VARCHAR NOT NULL
        CHECK (field_type IN ('text', 'number', 'select', 'date', 'url', 'checkbox')),
    options JSONB,
    is_required BOOLEAN NOT NULL DEFAULT false,
    position SMALLINT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (project_id, name)
);
CREATE INDEX idx_project_custom_fields_project_position
    ON project_custom_fields(project_id, position);

CREATE TABLE task_custom_field_values (
    task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    field_id UUID NOT NULL REFERENCES project_custom_fields(id) ON DELETE CASCADE,
    value TEXT,
    PRIMARY KEY (task_id, field_id)
);
```

## 3. API

URL 基底パスは `/v1/tenants/{tenant_id}/projects/{project_id}` である。

### フィールド定義（プロジェクトスコープ）

スコープは読み取りが `read:task`、書き込みが `write:task` で、プロジェクトに入れる人なら操作できる（テナントオーナーに限らない）。

| メソッド | パス | 説明 |
|---------|------|------|
| `GET` | `/custom-fields` | 定義一覧（`{ "fields": [...] }`。position 順） |
| `POST` | `/custom-fields` | 作成 |
| `PATCH` | `/custom-fields/{field_id}` | 更新（`name` / `options` / `is_required` / `position`。`field_type` は変えられない） |
| `DELETE` | `/custom-fields/{field_id}` | 削除（値も CASCADE） |

並び順を一括で更新する API は無く、`position` を 1 件ずつ更新する。`POST` で `position` を省略すると、既存の最大値の次になる。

`POST /custom-fields` リクエスト:

```json
{
  "name": "Story Points",
  "field_type": "select",
  "options": [
    { "label": "XS (1)", "value": "1" },
    { "label": "S (2)", "value": "2" },
    { "label": "M (3)", "value": "3" },
    { "label": "L (5)", "value": "5" },
    { "label": "XL (8)", "value": "8" }
  ],
  "is_required": false
}
```

`select` 型は `options` が必須で、空の配列・空の `label` / `value`・前後に空白のある `value`・`value` の重複は 400 になる。`select` 以外の型に `options` を渡しても 400 である。

### フィールド値（タスクスコープ）

値の専用エンドポイントは無い。[タスクの作成・更新・取得](/features/tasks/core)の `custom_field_values` で読み書きする。

`POST /tasks`・`PUT /tasks/{id}` のリクエストの一部:

```json
{
  "custom_field_values": [
    { "field_id": "uuid", "value": "5" },
    { "field_id": "uuid2", "value": "2026-07-01" },
    { "field_id": "uuid3", "value": null }
  ]
}
```

渡したフィールドだけを UPSERT する。`null` または空文字はその値を消す。同じ `field_id` の重複と、プロジェクトに無い `field_id` は 400 である。

`is_required=true` のフィールドの扱いは次のとおりである。

- 値を `null` や空文字にする入力は、ステータスに関係なく 400 になる
- タスクのステータスを `is_done_state=true` へ変更する・完了ステータスで作成するときに、既存の値と同じリクエストの値を合わせて未入力があれば 400 になる
- 未完了のまま作成・更新するだけなら、必須フィールドが未入力でも通る

`GET /tasks/{id}` のレスポンスの一部（プロジェクトの全フィールドを position 順に返し、値が無ければ `value` と `display_value` は `null`）:

```json
{
  "custom_field_values": [
    {
      "field": {
        "id": "uuid", "name": "Story Points", "field_type": "select",
        "is_required": false, "position": 0
      },
      "value": "5",
      "display_value": "L (5)"
    }
  ]
}
```

`display_value` は `select` 型なら選択肢の `label`、他の型なら `value` そのものである。

## 4. フロントエンド

### 管理画面（実装済み）

プロジェクト設定（`/{tenant}/projects/{KEY}/settings`）の「カスタムフィールド」で、定義の一覧・作成・編集・削除を行う（`components/projects/CustomFieldsSection.vue`）。`select` 型は選択肢を編集できる。ドラッグでの並び替えは無い。

### タスク詳細の値の入力（未実装）

タスク詳細にカスタムフィールドの欄は無く、値の表示も入力もできない。値を読み書きできるのは API だけである（CLI にも値を設定する引数は無い）。計画では、タスク詳細の右ペインに型ごとの入力欄を並べる。
