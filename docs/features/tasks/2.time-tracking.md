## 1. データモデル

### 1.1 `time_logs`

```rust
pub struct Model {
    pub id: Uuid,
    pub task_id: Uuid,
    pub user_id: Uuid,
    pub logged_minutes: i32,   // 分単位で保持（表示時に h/m 変換）
    pub logged_at: NaiveDate,  // 作業日
    pub note: Option<String>,
    pub created_at: DateTimeUtc,
}
```

| カラム | 型 | 制約 |
|--------|-----|------|
| `id` | UUID | PK |
| `task_id` | UUID | NOT NULL, FK→tasks CASCADE |
| `user_id` | UUID | NOT NULL, FK→users CASCADE |
| `logged_minutes` | INT | NOT NULL CHECK (> 0) |
| `logged_at` | DATE | NOT NULL |
| `note` | TEXT | NULLABLE |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT now() |

### 1.2 `task_timers`（アクティブタイマー）

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| `task_id` | UUID | NOT NULL, FK→tasks CASCADE | |
| `user_id` | UUID | NOT NULL, FK→users CASCADE | |
| `started_at` | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| — | — | PRIMARY KEY(task_id, user_id) | 同一ユーザーが同タスクに同時起動 1 つのみ |

タイマーを停止すると `task_timers` の行を消し、経過時間を `time_logs` へ 1 行入れる。この 2 つは同じトランザクションで行う。

- `logged_minutes` は経過秒数を分へ切り上げた値で、最低 1 分である
- `logged_at` は停止時刻を UTC+9 に固定して取った日付である（利用者のタイムゾーンは見ない）
- `note` は NULL で入る。停止時にメモを受け取る引数は無いので、後から `PUT` で足す

## 2. マイグレーション

```sql
CREATE TABLE time_logs (
    id UUID PRIMARY KEY,
    task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    logged_minutes INT NOT NULL CHECK (logged_minutes > 0),
    logged_at DATE NOT NULL,
    note TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE task_timers (
    task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (task_id, user_id)
);

CREATE INDEX idx_time_logs_task ON time_logs(task_id);
CREATE INDEX idx_time_logs_user_date ON time_logs(user_id, logged_at);
```

## 3. API

URL 基底パスは `/v1/tenants/{tenant_id}/projects/{project_id}` で、スコープは読み取りが `read:task`、書き込みが `write:task` である。

| メソッド | パス | 説明 |
|---------|------|------|
| `GET` | `/tasks/{id}/time-logs` | ログ一覧（作業日の新しい順） |
| `POST` | `/tasks/{id}/time-logs` | 手動ログ追加 |
| `PUT` | `/tasks/{id}/time-logs/{log_id}` | ログ編集（自分のログのみ。`clear_note` でメモを消す） |
| `DELETE` | `/tasks/{id}/time-logs/{log_id}` | 削除（自分 or テナントオーナー） |
| `POST` | `/tasks/{id}/timer/start` | タイマー開始。既に動いていれば 409 |
| `POST` | `/tasks/{id}/timer/stop` | タイマー停止 → ログ生成。動いていなければ 409 |
| `GET` | `/tasks/{id}/timer/status` | 呼び出した本人のタイマー状態 |
| `GET` | `/tasks/{id}/time-logs/summary` | 工数サマリー |

### POST `/tasks/{id}/time-logs`

```json
{
  "logged_minutes": 90,
  "logged_at": "2026-05-27",
  "note": "設計レビュー対応"
}
```

### POST `/tasks/{id}/timer/stop` レスポンス

```json
{
  "id": "uuid",
  "task_id": "uuid",
  "user_id": "uuid",
  "logged_minutes": 47,
  "logged_at": "2026-05-27",
  "note": null,
  "created_at": "2026-05-27T11:17:00Z"
}
```

### GET `/tasks/{id}/time-logs/summary`

`actual_minutes` は担当者以外の記録も含むタスク単位の合計である。[スケジュール](/features/tasks/schedule)の `logged_minutes` も同じ定義にしている。`estimated_minutes` が無いタスクでは `remaining_minutes` が `null`、`is_over` が `false` になる。`remaining_minutes` は実績が見積を超えると負の値になる。

```json
{
  "estimated_minutes": 180,
  "actual_minutes": 90,
  "remaining_minutes": 90,
  "is_over": false,
  "by_user": [
    { "user_id": "uuid", "name": "tanaka", "minutes": 60 },
    { "user_id": "uuid", "name": "suzuki", "minutes": 30 }
  ]
}
```

### GET `/tasks/{id}/timer/status`

タイマーが動いていないときは `is_running` が `false` で、他の 2 つは `null` である。

```json
{
  "is_running": true,
  "started_at": "2026-05-27T10:30:00Z",
  "elapsed_minutes": 25
}
```

## 4. フロントエンド（未実装）

タイマーと作業ログの画面はまだ無い。作業記録の合計は、[山積み](/features/tasks/workload)の残工数の計算にだけ使っている。タスク詳細は見積（`estimated_minutes`）を表示する。

計画している画面は次のとおりである。

- タスク詳細の右ペインにタイマーのウィジェットを置き、見積・実績と、開始ボタンまたは経過時間つきの停止ボタンを出す
- 起動中はリアルタイムの経過時間を表示する
- 停止時に任意のメモを入力してからログを保存する
