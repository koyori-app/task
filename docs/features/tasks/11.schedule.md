# スケジュール 仕様書

> ステータス: **実装済み（API・画面）** / 作成日: 2026-10-16
> **依存: [コア](/features/tasks/core)（`planned_start_on`）・[スプリント](/features/tasks/sprints)**

---

## 1. 概要

テナントカレンダー（タイムライン）とデスクトップ・CLI クライアントが、1 回の呼び出しで描画に
足りるデータを取るための読み取り専用 API。指定した期間に重なるタスクと、同じ期間に重なる
スプリント・マイルストーン、ページ内タスクの担当者をまとめて返す。画面は 5 節。

---

## 2. API

```
GET /v1/tenants/{tenant_id}/schedule
```

### 2.1 クエリ

| クエリ | 内容 |
|---|---|
| `from` / `to` | 必須。日付（`YYYY-MM-DD`）。両端含む。`from > to` または `to - from > 92 日` は 400 |
| `timezone` | IANA 名。既定 `UTC`。100 文字超・Postgres が知らない名前は 400 |
| `project_id` | 繰り返し指定可（`?project_id=a&project_id=b`）。可視プロジェクトとの積。見えない ID は黙って落とす |
| `user_id` | 繰り返し指定可。担当者（`task_assignees.user_id`）のいずれかに当たるタスクに絞る |
| `include_done` | 既定 true。false なら完了ステータス（`is_done_state = true`）のタスクを除く |
| `include_overdue` | 既定 false。true なら締切超過のタスク（Soft 締切・開始予定日・見積があり、終点が `from` より前で未完了のもの）も返す。[山積み](/features/tasks/workload)で締切超過の残工数を今日に積むために使う |
| `cursor` / `limit` | タスクのページング。`limit` 既定 200、1〜500（範囲外は 400）。壊れたカーソルは 400 |

### 2.2 応答

```json
{
  "range": { "from": "2026-10-12", "to": "2026-10-25", "timezone": "Asia/Tokyo" },
  "tasks": [{
    "id": "…", "seq_id": 59, "seq_key": "TASK-59", "title": "…",
    "project": { "id": "…", "key": "TASK", "name": "…", "is_personal": false },
    "status": { "id": "…", "name": "In Progress", "color": "…", "is_done_state": false },
    "priority": "high", "progress_pct": 40,
    "planned_start_on": "2026-10-21",
    "soft_deadline": "2026-10-27T14:59:59Z", "hard_deadline": null,
    "estimated_minutes": 960, "logged_minutes": 300,
    "assignees": [{ "user_id": "…", "role": "primary" }],
    "sprint_id": "…", "milestone_id": null
  }],
  "sprints": [{ "id": "…", "project_id": "…", "name": "Sprint 15", "goal": null, "start_date": "…", "end_date": "…", "status": "active", "...": "SprintResponse と同じ" }],
  "milestones": [{ "id": "…", "project_id": "…", "name": "…", "due_date": "…", "...": "MilestoneResponse と同じ" }],
  "members": [{ "id": "…", "username": "…", "avatar_url": null }],
  "next_cursor": null
}
```

- `project` / `status` / `members` の要素は My Tasks・ユーザー要約と同じ型（`MyTaskProjectInfo` /
  `MyTaskStatusInfo` / `UserSummary`）
- `logged_minutes` はそのタスクの作業記録（`time_logs.logged_minutes`）の合計。担当者以外の記録も含み、
  記録が無ければ 0。`GET /tasks/{id}/time-logs/summary` の `actual_minutes` と同じ定義で、SQL 側で集計する
  （[山積み](/features/tasks/workload) の残工数に使う）
- `assignees.role` は保存されている文字列をそのまま返す（`primary` と `assignee` が混在する）
- `sprints` / `milestones` はプロジェクト単体の API と同じ形（`SprintResponse` / `MilestoneResponse`）で、
  **全ページに同じものを載せる**（ページングしない）
- `members` はそのページの `tasks` の担当者を重複なく集めたもの
- `next_cursor` は次ページがあるときだけ入る

---

## 3. 含める条件

タスク:

- アーカイブ済み・削除済みは除く
- 締切は `timezone` で日付に落とす（DB 側で `AT TIME ZONE`）
  - 締切の日付 = Soft 締切の日付 → 無ければ Hard 締切の日付
  - 始点 = `planned_start_on` と締切の日付の早い方、終点 = 遅い方。片方しか無ければ両端ともその日
  - `planned_start_on` が締切より後のタスク（コアが許している）も、締切の日〜開始予定日として扱う
  - 3 つとも無いタスクは含めない
- 始点 <= `to` かつ 終点 >= `from` のものを返す。`include_overdue=true` なら、終点 < `from` でも
  Soft 締切・開始予定日・見積があり未完了のもの（山積みに積めるもの）を足す
- 並びは 始点 ASC、`id` ASC で固定。カーソルは `(始点, id)` の keyset

スプリントは `start_date <= to AND end_date >= from`、マイルストーンは `due_date` が
`from`〜`to` に入るもの。いずれも下記の可視プロジェクト（`project_id` 指定時はその積）に限る。
`user_id` / `include_done` はタスクにだけ効く。

---

## 4. 認可

- スコープは `read:task`。セッション・PAT・Device Token のいずれでも通る
- テナントに入れること（`ensure_tenant_access_or_guest_scope`）。テナントに入れない客分は
  明示メンバーのプロジェクトだけに絞る
- 候補はテナントの個人プロジェクト以外の全プロジェクト。テナントオーナーは全件、それ以外は
  `visible_project_ids`（メンバー指定のあるプロジェクトは指定された人だけ）で絞る
- 個人プロジェクト（自分の Inbox を含む）のタスクは返さない
- プロジェクト束縛付き PAT（`allowed_project_ids` あり）は 403（My Tasks と同じ）

## 5. 画面（`/{tenant}/calendar`）

行がメンバー、横軸が日付の 2 週間のタイムライン。データはこの API だけから作る
（`limit=500`、`next_cursor` を辿って全件）。URL は [URL 仕様](/frontend/url-spec)。

- 固定（MVP）: 月曜始まり・土日非稼働・1 日の上限 6h・祝日なし。週・月ビューは無い
- `timezone` はブラウザのタイムゾーン。締切の日付への落とし方は 3 節と同じ
- 行の見出し: 担当者のアバター（`members[].avatar_url`。無ければ頭文字）と名前。担当者なしの行は人のアイコン
- 帯: 始点 `planned_start_on`〜終点（3 節）。開始予定日の無いタスクは締切の点（菱形）。
  範囲外は端で切り詰めて矢印。主担当（`role = primary`）は塗り、それ以外は薄い枠線。
  完了はグレー、Soft 締切を過ぎた未完了は警告色
- 帯のクリックで、タスク一覧の List 表示と同じ詳細のオーバーレイを開く（子タスク・説明の KEY-N も
  オーバーレイ内で開き、閉じると元のタスクへ戻る）。狭い画面（1024px 未満）と修飾キー付きの
  クリックは従来どおり詳細ページ
- 最上段: 期間に重なるスプリントとマイルストーン（期日に旗）。重なるものは段を分ける
- メンバー・プロジェクトの絞り込みはクライアント側（候補は応答の `members` / `tasks[].project`）
- 見積/日: 主担当で、開始予定日と Soft 締切と見積があり、未完了のタスクについて

  ```
  見積/日 = estimated_minutes / 60 ÷ 平日数(planned_start_on 〜 Soft 締切の日付、両端含む)
  ```

  を各平日に足す。6h を超えた日は「超過」を出す
- 開始予定日はタスク作成ダイアログと詳細で入力する。Soft 締切より後の日付は送らずに警告する
  （サーバーは前後関係を検証しない）

---

## 6. 決定事項

- 期間の上限は 92 日（約 3 か月）。タイムライン 1 画面ぶんに収め、1 回の問い合わせを有界にする
- 期間判定とタイムゾーン変換は SQL 側で行い、Rust 側で全件を取って絞らない
- ページングはタスクだけ。スプリント・マイルストーン・担当者は期間あたりの件数が小さいので
  毎ページに載せ、クライアントがページを継いでも描画に要る周辺データが揃うようにする
- `read:task` だけでスプリント・マイルストーンも返す。タスクの文脈（属するスプリント・期日）として
  表示するためで、プロジェクト単体の API の `read:sprint` / `read:milestone` は変えない
- 個人プロジェクトはテナントの共有カレンダーに混ぜない（自分の Inbox は My Tasks で見る）
- テナントオーナーは dashboard・プロジェクト一覧と同じく全プロジェクトを見る
- 担当者の `role` の正規化（`primary` / `assignee` の混在）はこの API ではやらない
